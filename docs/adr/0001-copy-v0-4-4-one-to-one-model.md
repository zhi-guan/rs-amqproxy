# 复刻 v0.4.4 的一对一连接模型，不做 v3 的共享连接模型

生产环境目前使用 cloudamqp/amqproxy v0.4.4。它在长期运行后内存持续增长，而新版本无法在旧机器（CentOS 7.4）上编译。因此我们用 Rust 复刻 v0.4.4 的对外接口和行为：一个客户端连接在任一时刻只绑定一个上游连接，断开后按池 Key 归还到连接池。v2/v3 的"多个客户端共享一个上游连接并重映射 channel 编号"的模型，我们没有采用。

## 考虑过的方案

- **v3 共享模型**：上游连接更少，但需要做 channel 编号重映射和多客户端帧路由，复杂度和出错风险高很多。我们的客户端从没在这种模型下运行过。以后有需要时再单独评估。

## 影响

- 对外接口以 v0.4.4 为准：`-l/-p/-d/-h/-v`、位置参数上游 URL、`LISTEN_ADDRESS`/`LISTEN_PORT`/`AMQP_URL`、默认 `localhost:5673`、二进制名 `amqproxy`。
- 只新增两项：`-t/--idle-connection-timeout`（默认 5 秒，与后续版本同名），以及每 5 秒一行带 RSS 的统计日志。
