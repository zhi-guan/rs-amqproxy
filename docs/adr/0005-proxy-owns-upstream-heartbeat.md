# 代理自己维护上游心跳，客户端侧心跳保持为 0

v0.4.4 在客户端和上游两侧都协商 heartbeat=0。我们的 Broker 是阿里云 RabbitMQ 版，它会关闭长时间空闲的连接（ALL_IDLE）。而我们的常驻消费者（php-amqplib 3.1.0，heartbeat=0，keepalive=false）可能长时间没有任何流量。

因此，上游连接使用 Broker 建议的心跳值（如果 Broker 给 0，就用 60 秒）。代理主动发送心跳，如果在规定时间内没有收到数据，就判定上游连接已死，关闭它和它绑定的客户端连接。

客户端侧保持 v0.4.4 的行为：Tune 时给 heartbeat=0；收到客户端的心跳帧时，代理直接回送。代理不会因为客户端空闲而关闭客户端连接。客户端突然掉线（半开连接）由 TCP keepalive（60s/10s/3 次）发现。
